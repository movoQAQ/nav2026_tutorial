一、实验目标

ROS 2 提供 std_msgs、sensor_msgs 等标准消息类型。当一条 Topic 消息需要同时描述多个业务字段时，可以使用自定义的 .msg 消息类型。

本次实验要求完成如下通信过程：发布者每隔 1 秒发布一次机器人的编号、电量及激活状态，订阅者接收自定义消息并在终端输出。

通过实验理解以下内容：

  • 自定义消息包与功能节点包各自负责什么；
  • .msg 如何通过 rosidl 生成可供 C++ 调用的消息类型；
  • 发布者、订阅者如何使用同一个自定义消息；
  • 如何通过 colcon 编译、ros2 run 运行和 ros2 topic 检查通信。

三、配置自定义消息包 custom_interfaces

1. 定义 RobotStatus 消息

打开 src/custom_interfaces/msg/RobotStatus.msg，写入三个字段：

ROS .msg
int32 id
float32 battery_level
bool is_active
字段 类型 含义
id int32 机器人编号
battery_level float32 电量百分比，例如 87.5
is_active bool 机器人是否处于激活状态

2. 补充 custom_interfaces/CMakeLists.txt

打开 src/custom_interfaces/CMakeLists.txt。在现有的 find_package(ament_cmake REQUIRED) 之后，补充：

CMake
find_package(rosidl_default_generators REQUIRED)

rosidl_generate_interfaces(${PROJECT_NAME}
  "msg/RobotStatus.msg"
)

ament_export_dependencies(rosidl_default_runtime)

3. 补充 custom_interfaces/package.xml

打开 src/custom_interfaces/package.xml，在 <package> 内、已有的 <export> 外面增加以下内容：

XML
<build_depend>rosidl_default_generators</build_depend>
<exec_depend>rosidl_default_runtime</exec_depend>
<member_of_group>rosidl_interface_packages</member_of_group>

保留仓库已有的 ament_cmake、测试依赖、维护者信息及 <export> 标签。特别注意：<member_of_group> 是 <package> 的直接子元素，不能放到 <export> 内。

四、编写与配置通信节点 custom_msg_demo

1. 编写发布者 robot_status_publisher.cpp

打开 src/custom_msg_demo/src/robot_status_publisher.cpp，填写完整代码：

C++
#include <chrono>
#include <functional>
#include <memory>

#include "rclcpp/rclcpp.hpp"
#include "custom_interfaces/msg/robot_status.hpp"

using namespace std::chrono_literals;

class RobotStatusPublisher : public rclcpp::Node
{
public:
  RobotStatusPublisher() : Node("robot_status_publisher")
  {
    publisher_ = this->create_publisher<custom_interfaces::msg::RobotStatus>(
      "robot_status", 10);

    timer_ = this->create_wall_timer(
      1s, std::bind(&RobotStatusPublisher::timer_callback, this));
  }

private:
  void timer_callback()
  {
    custom_interfaces::msg::RobotStatus msg;
    msg.id = 1;
    msg.battery_level = 87.5f;
    msg.is_active = true;

    publisher_->publish(msg);
    RCLCPP_INFO(
      this->get_logger(), "发布: id=%d, 电量=%.2f%%, 激活状态=%s",
      msg.id, msg.battery_level, msg.is_active ? "true" : "false");
  }

  rclcpp::Publisher<custom_interfaces::msg::RobotStatus>::SharedPtr publisher_;
  rclcpp::TimerBase::SharedPtr timer_;
};

int main(int argc, char * argv[])
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<RobotStatusPublisher>());
  rclcpp::shutdown();
  return 0;
}

观察重点： create_publisher<T>() 中的 T 是自定义消息类型；create_wall_timer(1s, ...) 每秒调用一次回调；回调中对三个字段赋值并调用 publish()。

2. 编写订阅者 robot_status_subscriber.cpp

打开 src/custom_msg_demo/src/robot_status_subscriber.cpp，填写完整代码：

C++
#include <functional>
#include <memory>

#include "rclcpp/rclcpp.hpp"
#include "custom_interfaces/msg/robot_status.hpp"

class RobotStatusSubscriber : public rclcpp::Node
{
public:
  RobotStatusSubscriber() : Node("robot_status_subscriber")
  {
    subscription_ = this->create_subscription<custom_interfaces::msg::RobotStatus>(
      "robot_status", 10,
      std::bind(&RobotStatusSubscriber::topic_callback, this, std::placeholders::_1));
  }

private:
  void topic_callback(const custom_interfaces::msg::RobotStatus & msg) const
  {
    RCLCPP_INFO(
      this->get_logger(), "接收: id=%d, 电量=%.2f%%, 激活状态=%s",
      msg.id, msg.battery_level, msg.is_active ? "true" : "false");
  }

  rclcpp::Subscription<custom_interfaces::msg::RobotStatus>::SharedPtr subscription_;
};

int main(int argc, char * argv[])
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<RobotStatusSubscriber>());
  rclcpp::shutdown();
  return 0;
}

观察重点： create_subscription<T>() 中使用的消息类型、话题名必须与发布者一致；订阅者通过回调接收数据，std::placeholders::_1 表示传入回调的消息参数。

3. 补充 custom_msg_demo/CMakeLists.txt

打开 src/custom_msg_demo/CMakeLists.txt。

在现有的 find_package(custom_interfaces REQUIRED) 后面、if(BUILD_TESTING) 前面，补充以下代码：

CMake
add_executable(robot_status_publisher src/robot_status_publisher.cpp)
ament_target_dependencies(robot_status_publisher rclcpp custom_interfaces)

add_executable(robot_status_subscriber src/robot_status_subscriber.cpp)
ament_target_dependencies(robot_status_subscriber rclcpp custom_interfaces)

install(TARGETS
  robot_status_publisher
  robot_status_subscriber
  DESTINATION lib/${PROJECT_NAME}
)

add_executable 定义编译目标，ament_target_dependencies 为目标指定依赖，install(TARGETS ...) 使 ros2 run 能找到程序。原文件末尾的 ament_package() 要保留。

4. 确认节点包依赖（无需修改）

此文件在仓库中已经声明 rclcpp 和 custom_interfaces 依赖，本实验无需修改。了解节点包为什么需要依赖消息接口包即可。

五、编译、运行与验证

1. 编译两个功能包

回到 lecture2/task1 根目录执行（假设已处于配置正常的 Humble 终端）：

Bash
cd ~/nav2026_tutorial/lecture2/task1
colcon build --symlink-install
source install/setup.bash

2. 验证自定义消息接口

Bash
ros2 interface show custom_interfaces/msg/RobotStatus

预期显示：

ROS .msg
int32 id
float32 battery_level
bool is_active

3. 启动发布者与订阅者

终端 A：

Bash
cd ~/nav2026_tutorial/lecture2/task1
source install/setup.bash
ros2 run custom_msg_demo robot_status_publisher

终端 B（新终端）：

Bash
cd ~/nav2026_tutorial/lecture2/task1
source install/setup.bash
ros2 run custom_msg_demo robot_status_subscriber

新终端需要加载当前工作空间的 install/setup.bash，以便识别刚刚编译生成的接口和节点。预期可以看到类似日志（日志前的时间戳省略）：

Text
[INFO] [robot_status_publisher]: 发布: id=1, 电量=87.50%, 激活状态=true
[INFO] [robot_status_subscriber]: 接收: id=1, 电量=87.50%, 激活状态=true

4. 验证话题通信

终端 C（新终端）：

Bash
cd ~/nav2026_tutorial/lecture2/task1
source install/setup.bash
ros2 topic list
ros2 topic type /robot_status
ros2 topic echo /robot_status

ros2 topic type /robot_status 应返回 custom_interfaces/msg/RobotStatus。ros2 topic echo /robot_status 应连续输出：

YAML
id: 1
battery_level: 87.5
is_active: true
---

如需查看发布者、订阅者和 QoS 信息，可执行 ros2 topic info /robot_status --verbose；也可运行 rqt_graph 查看节点与 Topic 的连线（选做）。
