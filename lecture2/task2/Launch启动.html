一、实验目标与 Launch 的作用

上一节分别使用 ros2 run 启动发布者与订阅者。本节使用一个 Python Launch 文件统一启动两者，进一步练习 节点参数、条件启动、延时启动、重映射与模块化引入。

  • 理解 generate_launch_description() 与 LaunchDescription、Node 的职责。
  • 利用已提供的 robot_status_bringup 功能包安装 Launch 文件，并执行 ros2 launch。
  • 使用 ros2 node、ros2 topic 检查 Launch 结果；知道 Launch 参数与节点参数的区别。

学习顺序： 基础实验只需要完成第二至六节；后续为进阶练习和原讲义知识点整理。为了保证能够运行，所有基础代码均使用仓库当前已经存在的真实包名、文件路径及 C++ 可执行程序名。

发布者参考源码（可展开）

C++
#include <chrono>
#include <functional>
#include <memory>

#include "rclcpp/rclcpp.hpp"
#include "custom_interfaces/msg/robot_status.hpp"

using namespace std::chrono_literals;

class RobotStatusPublisher : public rclcpp::Node
{
public:
  RobotStatusPublisher() : Node("robot_status_publisher")
  {
    publisher_ = this->create_publisher<custom_interfaces::msg::RobotStatus>(
      "robot_status", 10);

    timer_ = this->create_wall_timer(
      1s, std::bind(&RobotStatusPublisher::timer_callback, this));
  }

private:
  void timer_callback()
  {
    custom_interfaces::msg::RobotStatus msg;
    msg.id = 1;
    msg.battery_level = 87.5f;
    msg.is_active = true;

    publisher_->publish(msg);
    RCLCPP_INFO(
      this->get_logger(), "发布: id=%d, 电量=%.2f%%, 激活状态=%s",
      msg.id, msg.battery_level, msg.is_active ? "true" : "false");
  }

  rclcpp::Publisher<custom_interfaces::msg::RobotStatus>::SharedPtr publisher_;
  rclcpp::TimerBase::SharedPtr timer_;
};

int main(int argc, char * argv[])
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<RobotStatusPublisher>());
  rclcpp::shutdown();
  return 0;
}

四、编写第一个能够运行的 Launch 文件

1. 核心结构：LaunchDescription 与 Node

编辑 src/robot_status_bringup/launch/robot_status.launch.py，写入以下完整代码：

Python · Launch
from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():
    publisher = Node(
        package='robot_status_publisher',
        executable='robot_status_publisher',
        name='robot_status_publisher',
        output='screen',
    )

    subscriber = Node(
        package='robot_status_subscriber',
        executable='robot_status_subscriber',
        name='robot_status_subscriber',
        output='screen',
    )

    return LaunchDescription([publisher, subscriber])
关键对象作用本实验体现
generate_launch_description()Python Launch 入口函数返回待启动的动作列表
LaunchDescription声明一次启动包含哪些动作同时启动发布者与订阅者
Node声明 ROS 2 节点进程包名、可执行程序名、显示名
output="screen"将进程输出显示到终端课堂观察发送/接收日志

六、Launch 参数与条件启动（必做改进）

将 Launch 配置为：始终启动发布者，订阅者是否启动由命令行参数 use_subscriber 决定。用以下完整代码替换第四节的 Launch 文件。

Python · Launch
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument
from launch.conditions import IfCondition
from launch.substitutions import LaunchConfiguration
from launch_ros.actions import Node


def generate_launch_description():
    use_subscriber = LaunchConfiguration('use_subscriber')

    return LaunchDescription([
        DeclareLaunchArgument(
            'use_subscriber',
            default_value='true',
            description='Whether to launch the subscriber',
        ),
        Node(
            package='robot_status_publisher',
            executable='robot_status_publisher',
            name='robot_status_publisher',
            output='screen',
        ),
        Node(
            package='robot_status_subscriber',
            executable='robot_status_subscriber',
            name='robot_status_subscriber',
            output='screen',
            condition=IfCondition(use_subscriber),
        ),
    ])

完成修改后重新编译并分别测试：

Bash
cd ~/nav2026_tutorial/lecture2/task2
colcon build --symlink-install --packages-select robot_status_bringup
source install/setup.bash

# 查看可用 Launch 参数
ros2 launch robot_status_bringup robot_status.launch.py --show-args

# 默认启动发布者 + 订阅者
ros2 launch robot_status_bringup robot_status.launch.py

# 关闭订阅者（Ctrl+C 退出上一条命令后运行）

DeclareLaunchArgument 声明参数及默认值；LaunchConfiguration 表示运行时读取该参数，并不是马上读取到普通 Python 字符串；IfCondition 根据解析后的值决定是否启动节点。反向条件可使用 UnlessCondition。

七、TimerAction：延迟启动与顺序控制

需求：订阅者立即启动，发布者延迟 2 秒启动。在第六节的文件中添加导入 TimerAction，再把 发布者的 Node 动作 包进 TimerAction。以下是可直接替换的完整版本：

Python · Launch
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument, TimerAction
from launch.conditions import IfCondition
from launch.substitutions import LaunchConfiguration
from launch_ros.actions import Node


def generate_launch_description():
    use_subscriber = LaunchConfiguration('use_subscriber')

    publisher = Node(
        package='robot_status_publisher',
        executable='robot_status_publisher',
        output='screen',
    )
    subscriber = Node(
        package='robot_status_subscriber',
        executable='robot_status_subscriber',
        output='screen',
        condition=IfCondition(use_subscriber),
    )

    return LaunchDescription([
        DeclareLaunchArgument('use_subscriber', default_value='true'),
        subscriber,
        TimerAction(period=2.0, actions=[publisher]),
    ])

运行同一个 ros2 launch robot_status_bringup robot_status.launch.py，观察前 2 秒只有订阅者存在，随后发布者启动并开始发送数据。TimerAction 是计时后触发动作，不会阻塞其他动作；它也不保证业务上的“节点准备就绪”。

八、Node 的常用配置：命名、命名空间和重映射

字段用途示例
package定位 ROS 2 功能包robot_status_publisher
executable可执行文件名robot_status_publisher
name运行时节点名称status_pub
namespace设置节点命名空间robot1
remappings把原始话题或服务名映射到新名字("robot_status", "status")
parameters传递 ROS 参数或参数文件[params_path]
arguments程序命令行参数（并非 ROS 参数）["--help"]
output启动进程的日志显示位置"screen"

1. 实验：两节点统一重映射

你可以临时把第四节的两个 Node 都改为带以下配置（仅展示 Node，其他 Launch 结构保持不变）：

Python · Launch
publisher = Node(
    package='robot_status_publisher',
    executable='robot_status_publisher',
    remappings=[('robot_status', 'robot_status_debug')],
    output='screen',
)
subscriber = Node(
    package='robot_status_subscriber',
    executable='robot_status_subscriber',
    remappings=[('robot_status', 'robot_status_debug')],
    output='screen',
)

两者都重映射后，应使用 ros2 topic echo /robot_status_debug 验证；只改一个节点可能导致双方不再通信。

2. 选做：GroupAction + PushRosNamespace

把多个动作放进同一个分组，统一设置 /robot1 命名空间：

Python · Launch
from launch.actions import GroupAction
from launch_ros.actions import Node, PushRosNamespace

robot_group = GroupAction(actions=[
    PushRosNamespace('robot1'),
    Node(package='robot_status_publisher', executable='robot_status_publisher'),
    Node(package='robot_status_subscriber', executable='robot_status_subscriber'),
])
# 在 generate_launch_description() 中：
# return LaunchDescription([robot_group])

两段 C++ 都使用相对话题名 robot_status 时，最终话题为 /robot1/robot_status。如果 C++ 中把话题写死为 /robot_status（绝对路径），命名空间不会自动改变它。

九、参数文件 YAML 与节点参数（进阶实践）

Launch 文件有两类容易混淆的“参数”：Launch 参数（如 use_subscriber）决定如何组织启动；ROS 节点参数（如 publish_frequency）改变节点自身行为，后者需要 C++ 节点主动声明、读取或处理。

1. 先让发布者支持 publish_frequency

上一节的发布者使用固定 1s 定时器，没有声明 publish_frequency。请在发布者的构造函数中，将原本的定时器创建部分替换为：

C++
// 其余 publisher_ 和 timer_callback() 代码保持不变
const double hz = this->declare_parameter<double>("publish_frequency", 1.0);
const double safe_hz = hz > 0.0 ? hz : 1.0;
const auto period = std::chrono::duration<double>(1.0 / safe_hz);

timer_ = this->create_wall_timer(
  period, std::bind(&RobotStatusPublisher::timer_callback, this));

发布者的源文件已有 #include <chrono> 与 #include <functional>，因此这里无需增加新的头文件。这个例子在启动时读取一次频率参数，并不实现运行中动态调整定时器。

十、模块化启动：IncludeLaunchDescription（选做）

当项目规模较大时，可以把发布者启动拆成一个子 Launch，再由主 Launch 引用。此例是演示组合关系，不应与主文件中原有的 publisher 再次同时启动，否则会出现重复进程。

1. 子 Launch：publisher.launch.py

在 src/robot_status_bringup/launch/publisher.launch.py 新建文件：

Python · Launch
from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():
    return LaunchDescription([
        Node(
            package='robot_status_publisher',
            executable='robot_status_publisher',
            output='screen',
        )
    ])

2. 主 Launch 引入子 Launch

在主 Launch 中，用下列 IncludeLaunchDescription 替代原本直接启动的 publisher 动作（不要重复启动）。

Python · Launch
import os
from ament_index_python.packages import get_package_share_directory
from launch.actions import IncludeLaunchDescription
from launch.launch_description_sources import PythonLaunchDescriptionSource

# 放在 generate_launch_description() 内
share_dir = get_package_share_directory('robot_status_bringup')
child = IncludeLaunchDescription(
    PythonLaunchDescriptionSource(
        os.path.join(share_dir, 'launch', 'publisher.launch.py')
    )
)
# 在 LaunchDescription([...]) 中放入 child 和 subscriber

子 Launch 需要接受父 Launch 参数时，可使用 launch_arguments={"key": value}.items() 传递，子文件内使用 DeclareLaunchArgument 和 LaunchConfiguration 声明/读取。

十一、其他 Launch 机制速览（原讲义进阶内容）

1. 常见替换符 Substitutions

名称作用与注意点
LaunchConfiguration引用启动时的 Launch 参数；需在 Launch 上下文中解析，不是立即返回字符串
PathJoinSubstitution拼接文件路径，支持其他替换符作为路径片段
FindExecutable查询 PATH 上的程序，可用于 ExecuteProcess
Command在 Launch 运行期执行外部命令并取其输出；可能阻塞启动
TextSubstitution提供静态文本以便与其他替换符组合
PythonExpression计算简单表达式；不要直接执行不可信的输入
EnvironmentVariable读取环境变量及可选的默认值

2. 事件机制 Event handlers

OnProcessStart 可以响应进程启动，OnProcessExit 可以响应进程退出。下面是 API 结构示意：发布者退出后，再启动订阅者（只是为了理解事件，不是本实验推荐的正常启动方案）。

Python · Launch
from launch.actions import RegisterEventHandler
from launch.event_handlers import OnProcessExit

handler = RegisterEventHandler(
    OnProcessExit(target_action=publisher, on_exit=[subscriber])
)
# 与 publisher 一起放入 LaunchDescription([publisher, handler])

注意：OnProcessStart 也不等于 ROS 节点完成初始化或传感器准备就绪；OnProcessExit 通常会在正常退出或异常退出后触发，需要根据业务决定是否启动后续动作。

3. ComposableNodeContainer：为何本实验不直接使用

原讲义中的 ComposableNodeContainer、ComposableNode 和 LoadComposableNodes 属于组件化部署：多个注册为组件插件的 C++ 节点可以加载进一个进程。其典型写法是创建 component_container，并指定 ComposableNode(package=..., plugin=...)。

本仓库发布者/订阅者目前是普通 add_executable() 生成的独立进程，尚未编写并注册 rclcpp_components 插件，因此不能仅把 Node 改成 ComposableNode 就直接运行。此知识点保留作阅读扩展，不作为本次实验提交要求。
