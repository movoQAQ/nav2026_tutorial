ROS2 基础入门教程

一、ROS2 简介

1.1 什么是ROS2

  • Robot Operating System 2（机器人操作系统）
  • 模块化通信中间件 + 机器人开发工具集
  • 核心特性：
    • 实时性支持（基于DDS通信协议）
    • 跨平台（Linux/Windows/macOS/RTOS）
    • 分布式系统
    • 多语言支持（Python/C++/Java等）

1.2 为什么要用 ROS2？

在机器人开发中，硬件复杂、传感器繁多、软件模块众多。
如果我们直接用 C++ 写底层驱动、通信逻辑，会面临以下问题：

  • 通信复杂：传感器和控制器之间的数据传递需要自己写 socket、串口、共享内存等。
  • 模块耦合度高：代码越写越庞大，难以扩展和维护。
  • 跨平台困难：不同操作系统、不同硬件上需要重复修改。
  • 复用性差：别人写好的激光雷达驱动或定位算法，很难直接接入。

ROS2 的出现就是为了解决这些痛点：

  • 提供标准通信机制（话题、服务、动作） → 模块之间像乐高一样拼接。
  • 跨平台支持（Linux、Windows、嵌入式 RTOS） → 一份代码多处运行。
  • 生态丰富（现成的驱动包、算法库） → 节省大量开发时间。
  • 实时性更好（基于 DDS 通信） → 满足机器人实际需求。

1.3 ROS2 与底层代码实现架构的关系

我们可以把 ROS2 理解为一层“中间件”：

  • 最底层：硬件 & 驱动
    电机、传感器、摄像头 → 用 C/C++ 驱动直接操作。

  • 中间层：ROS2 框架
    用 C++ 封装通信接口（rclcpp），提供话题/服务/动作的标准 API。
    这一层解决“模块之间怎么交流”的问题。

  • 上层：应用逻辑
    定位、导航、视觉识别等算法模块，开发者用 C++ 或 Python 编写，直接调用 ROS2 API。

1.4 核心概念

  • 节点(Node)：执行单元
  • 话题(Topic)：发布/订阅通信模式
  • 服务(Service)：请求/响应模式
  • 动作(Action)：长时任务通信协议
  • 参数(Parameter)：动态配置

1.5 ROS 2 架构图讲解 (不用听懂)

ROS 2 的架构可以分为 五层，从底层到顶层依次是：

1. 操作系统层（Operating System Layer）

  • 支持 Linux、Windows、macOS 等。
  • 提供最底层的进程管理、线程调度、网络通信等功能。
  • ROS 2 并不替代操作系统，而是基于操作系统来运行。

类比：
操作系统就像“城市的道路和电力系统”，提供最基础的运行环境。

2. DDS 实现层（DDS Implementation Layer）

  • DDS（Data Distribution Service）是一种发布-订阅通信协议。
  • ROS 2 并没有自己造轮子，而是调用现成的 DDS 实现，比如：
    • eProsima Fast DDS
    • Eclipse Cyclone DDS
    • RTI Connext DDS
  • 不同 DDS 厂商的实现类似于“不同品牌的快递公司”。

类比：
DDS 就像“快递网络”，负责把消息从一个地方送到另一个地方。

3. 抽象 DDS 层（ROS Middleware Interface, rmw）

  • 由于 DDS 有多种实现，ROS 2 在 DDS 上面加了一层中间接口（rmw）。
  • 这样，上层开发者不需要关心具体用的是哪家 DDS，直接用 ROS API 就行。
  • 好处：屏蔽差异，统一接口。

类比：
rmw 就像“华理快递柜的统一取件码系统”，不管你用顺丰还是圆通，取快递的方式都是一样的。

4. ROS 2 客户端层（ROS 2 Client Layer）

  • 提供开发者常用的编程接口（API），主要包括：
    • rclcpp（C++ API）
    • rclpy（Python API）
    • 以及其他语言接口
  • 这一层的核心是 ROS 2 Client Library (rcl)，用 C 实现，向上封装给不同语言。

类比：
这一层就像“电话客服系统”：

  • 你用中文（Python）还是英文（C++）打电话都可以，客服会帮你转成统一的内部操作。

5. 应用层（Application Layer）

  • 最上层是开发者写的 用户代码（ROS 2 Nodes）。
  • 包含具体的功能模块，例如：
    • 激光雷达驱动节点
    • 定位算法节点
    • 导航控制节点
  • 这些节点之间通过话题、服务、动作来通信。

类比：
应用层就像“快递寄件人和收件人”，我们写的节点就是寄件人/收件人，信息通过 DDS 快递系统传递。

二、 ROS 2 工作空间架构

2.1. ROS 2 工作空间架构

ROS 2 的开发通常在 工作空间（workspace） 中完成。
一个标准的 ROS 2 工作空间目录结构如下：

ros2_ws/ # 工作空间根目录
├── src/ # 源代码目录（存放各个工作包）
│ ├── first_package/ # 示例工作包
│ └── ...
├── install/ # 编译后安装目录（生成的可执行文件、头文件等）
├── build/ # 编译的中间文件
└── log/ # 日志文件

2.2 使用cpp创建工作包并编译

2.2.1 创建工作包

在 ROS 2 中，工作包（package） 是最小的功能单元。
一个机器人系统由多个包组成，每个包负责一个功能（比如激光雷达驱动、路径规划，之间使用话题、行为、服务进行通信）。

创建工作包的命令：

# 进入工作空间的 src/ 目录
mkdir -p ~/teach/teach_ws/src && cd ~/teach/teach_ws/src

# 创建一个新的工作包
ros2 pkg create first_package --build-type ament_cmake --dependencies rclcpp

这里：

  • first_package 是包名。

  • --build-type ament_cmake 表示使用 CMake 构建（常用于 C++）。

  • --dependencies rclcpp 表示依赖 rclcpp 库（ROS 2 C++ 客户端库）。

创建完成后，工作空间的结构大概是：

ros2_ws/ # 工作空间根目录
├── src/ # 源代码目录（存放各个工作包）
│ ├── first_package/
| |     ├── CMakeLists.txt    # 构建规则
| |     ├── package.xml       # 包的描述信息
| |     └── src/              # 源代码存放目录
│ └── ...
├── install/ # 编译后安装目录（生成的可执行文件、头文件等）
├── build/ # 编译的中间文件
└── log/ # 日志文件

2.2.2 创建一个node

节点（Node） 是 ROS 2 程序的基本执行单元。 例如：一个激光雷达节点、一个导航节点、一个摄像头节点。

在刚才的 first_package/src/里新建一个 C++ 文件 my_node.cpp：

#include "rclcpp/rclcpp.hpp"

class MyNode : public rclcpp::Node {
public:
    MyNode() : Node("my_node") {
        RCLCPP_INFO(this->get_logger(), "Hello ROS2 Node!");
    }
};

int main(int argc, char **argv) {
    rclcpp::init(argc, argv);
    rclcpp::spin(std::make_shared<MyNode>());
    rclcpp::shutdown();
    return 0;
}

然后修改 CMakeLists.txt，加入：

add_executable(my_node src/my_node.cpp)
ament_target_dependencies(my_node rclcpp)
install(TARGETS my_node DESTINATION lib/${PROJECT_NAME})

编译并运行：

# 回到工作空间根目录
cd ~/teach/teach_ws

# 编译工作空间
colcon build

# 进入新环境
source install/setup.bash

# 运行节点
ros2 run first_package my_node

运行结果：

[INFO] [xxxx] [my_node]: Hello ROS2 Node!

2.3 使用 Python 创建工作包并编译

2.3.1 创建工作包

# 进入工作空间的 src/ 目录
cd ~/teach/teach_ws/src

# 创建一个新的工作包（Python版）
ros2 pkg create first_py_package --build-type ament_python --dependencies rclpy

这里：

  • first_py_package 是包名。
  • --build-type ament_python 表示使用 Python 构建。
  • --dependencies rclpy 表示依赖 rclpy 库（ROS 2 Python 客户端库）。

创建完成后，目录结构大概是：

ros2_ws/
├── src/
│   ├── first_py_package/
│   │   ├── package.xml        # 包的描述信息
│   │   ├── setup.py           # Python 安装脚本
│   │   ├── resource/          # 资源文件
│   │   └── first_py_package/  # Python 源码目录
│   │       └── __init__.py
│   └── ...
├── install/
├── build/
└── log/

2.3.2 创建一个 Node

在 first_py_package/first_py_package/ 下新建 my_node.py 文件：

import rclpy
from rclpy.node import Node

class MyNode(Node):
    def __init__(self):
        super().__init__("my_py_node")
        self.get_logger().info("Hello ROS2 Python Node!")

def main(args=None):
    rclpy.init(args=args)
    node = MyNode()
    rclpy.spin(node)
    rclpy.shutdown()

if __name__ == "__main__":
    main()

在 setup.py 中加入入口：

entry_points={
    'console_scripts': [
        'my_node = first_py_package.my_node:main',
    ],
},

编译并运行

# 回到工作空间根目录
cd ~/teach/teach_ws

# 编译工作空间
colcon build

# 进入新环境
source install/setup.bash

# 运行节点
ros2 run first_py_package my_node

运行结果：

[INFO] [xxxx] [my_py_node]: Hello ROS2 Python Node!

五、不同级别的日志输出

日志级别 宏名称 说明
INFO RCLCPP_INFO 输出一般信息，帮助开发者了解程序的状态。
WARN RCLCPP_WARN 输出警告信息，提醒潜在问题，通常不影响执行。
ERROR RCLCPP_ERROR 输出错误信息，通常会影响程序的执行。
FATAL RCLCPP_FATAL 输出致命错误，通常会导致节点崩溃或停止运行。
DEBUG RCLCPP_DEBUG 输出调试信息，帮助开发者跟踪程序执行过程。
TRACE RCLCPP_TRACE 最详细的日志信息，适用于深度调试，记录每个细节。

示例

RCLCPP_INFO(this->get_logger(), "This is an info log.");
RCLCPP_WARN(this->get_logger(), "This is a warning log.");
RCLCPP_ERROR(this->get_logger(), "This is an error log.");
RCLCPP_FATAL(this->get_logger(), "This is a fatal log.");
RCLCPP_DEBUG(this->get_logger(), "This is a debug log.");
RCLCPP_TRACE(this->get_logger(), "This is a trace log.");

# INFO log
self.get_logger().info('This is an INFO log.')
# WARN log
self.get_logger().warn('This is a WARN log.')
# ERROR log
self.get_logger().error('This is an ERROR log.')
# FATAL log
self.get_logger().fatal('This is a FATAL log.')
# DEBUG log
self.get_logger().debug('This is a DEBUG log.')
# TRACE log
self.get_logger().trace('This is a TRACE log.')

四、ROS 2 Node 相关命令行指令

除了编写节点代码以外，还需要熟悉常用的命令行工具来操作和调试节点。

1. 启动节点

# 运行某个包里的节点
ros2 run <package_name> <executable_name>

示例：

ros2 run first_package my_node
ros2 run first_py_package my_node

2. 查看节点

# 列出当前运行的所有节点
ros2 node list

输出示例：

/my_node
/my_py_node

3. 查看节点信息

# 查看某个节点的详细信息（话题、服务、参数等）
ros2 node info /my_node

输出示例：

/my_node
  Subscribers:
    /parameter_events: rcl_interfaces/msg/ParameterEvent
  Publishers:
    /rosout: rcl_interfaces/msg/Log
  Services:
    /my_node/get_parameter_types
    /my_node/list_parameters

4. 参数相关

# 列出节点的参数
ros2 param list

# 查看某个参数的值
ros2 param get /my_node param_name

# 设置某个参数
ros2 param set /my_node param_name value

四、ROS 2 命名空间、功能包、节点总结

4.1 创建命名空间的方式

mkdir -p <命名空间名>/src/
cd <命名空间名>/src/

4.2 创建功能包的方式

1. Python 功能包

ros2 pkg create <包名> --build-type ament_python --dependencies rclpy

2. C++ 功能包

ros2 pkg create <包名> --build-type ament_cmake --dependencies rclcpp

4.3 编写节点方式

通用流程：

  1. 导入库文件
  2. 初始化客户端库
  3. 新建节点
  4. spin 循环节点
  5. 关闭客户端库

1. Python 节点

在与 __init__.py 同级目录下创建 x.py。

setup.py 配置

entry_points={
    'console_scripts': [
        '<节点名> = <包名>.<py文件名>:main'
    ],
},

2. C++ 节点

在 src/ 下创建 x.cpp 文件。

CMakeLists.txt 配置

find_package(rclcpp REQUIRED)
find_package(<依赖名> REQUIRED)

add_executable(<节点名> src/<cpp文件名>.cpp)
ament_target_dependencies(<节点名> rclcpp <依赖名>)

install(TARGETS
  <节点名>
  DESTINATION lib/${PROJECT_NAME}
)

4.4 编译功能包

注意：必须返回到 src 的上一级目录（工作空间根目录）。

colcon build
source install/setup.bash

4.5 运行节点

ros2 run <包名> <节点名>
